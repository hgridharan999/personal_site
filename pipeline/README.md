# Flyover pipeline

Turns a hike's GPX track into what the site's 3D flyover (`/hiking/:slug`) streams:
terrain-RGB elevation tiles from USGS 3DEP, NAIP aerial-imagery tiles, web-sized photos,
and a `manifest.json`. Everything runs offline on your machine; the results go to
Cloudflare R2. Design: `docs/superpowers/specs/2026-09-27-hike-flyover-design.md`.

## Setup

```bash
cd pipeline
uv sync
```

Needs Python 3.12+ and [uv](https://docs.astral.sh/uv/). rasterio's wheels bundle GDAL,
so there's nothing else to install, on Windows included.

## Add a hike

1. Config (committed): `pipeline/hikes/<slug>.toml`. See `hikes/quandary.toml` for every option.
2. Track (gitignored): export the recording as GPX and save it as
   `pipeline/input/<slug>/track.gpx`. It must have timestamps.
3. Photos (gitignored, optional): copy the **original** files, not the resized copies in
   `public/hikes/`, into `pipeline/input/<slug>/photos/`. They need EXIF capture times.
   JPEG, PNG, and WebP work; convert HEIC to JPEG first.

## Build

```bash
uv run flyover build quandary      # one hike
uv run flyover build-all           # every hike that has a track.gpx
```

Output goes to `pipeline/out/`, laid out exactly as it will be on R2:

```
out/tiles/v1/dem/{z}/{x}/{y}.webp          elevation, shared by all hikes
out/tiles/v1/img/{year}/{z}/{x}/{y}.webp   imagery, shared by all hikes
out/hikes/<slug>/manifest.json
out/hikes/<slug>/photos/<hash>.webp
```

The build ends with a size report per layer and zoom, and warns above 80 MB. To shrink a
hike, lower `CORRIDOR_RADII_M` in `src/flyover/coverage.py`. Downloads are cached in
`pipeline/.cache/` and existing tiles are skipped, so re-runs are quick. Delete a tile
folder to force it to rebuild.

- **Rebuilt tiles don't re-upload:** upload skips keys already on R2, which are cached as
  immutable. To replace published tiles, bump `TILESET_VERSION` in `src/flyover/tilestore.py`
  (spec §5 stage 7) instead.
- **Cache size:** `pipeline/.cache/` can grow to about 1 GB.
- **New NAIP years:** delete `pipeline/.cache/naip/` to pick up a newly published NAIP year.

## Check a build

```bash
uv run python tools/check_dem.py quandary
```

Compares the elevation tiles with the manifest's summit (should agree within 3 m) and
writes `out/hikes/quandary/check-hillshade-z13.png` to look at.

```bash
uv run python -m http.server 8000
```

Then open <http://localhost:8000/tools/preview.html?slug=quandary> to see the imagery
tiles and the track on a map. Add `&borders` to see tile edges.

## Upload

```bash
uv run flyover upload quandary
```

Tiles and photos go up first and are skipped if they already exist on R2. The manifest
goes last, so the live site never sees a manifest whose tiles are missing.

### One-time R2 setup

1. In the Cloudflare dashboard, go to **R2**, create a bucket (e.g. `flyover`).
2. **R2 → Manage API tokens → Create API token** with *Object Read & Write* on that bucket
   only. Copy `.env.example` to `pipeline/.env` and fill in the account ID, the token's
   access key ID and secret, and the bucket name. `.env` is gitignored; never commit it.
3. Bucket **Settings → CORS policy**, so the site's WebGL code may read the tiles:

   ```json
   [
     {
       "AllowedOrigins": ["https://YOUR-SITE-DOMAIN", "http://localhost:5173"],
       "AllowedMethods": ["GET", "HEAD"],
       "AllowedHeaders": ["*"],
       "MaxAgeSeconds": 86400
     }
   ]
   ```

4. Bucket **Settings → Public access**: connect a custom domain (needs the domain's DNS on
   Cloudflare) or enable the `r2.dev` URL (rate-limited; for testing only). That public
   URL is the site's `VITE_FLYOVER_BASE_URL`.

## Develop

```bash
uv run pytest
uv run ruff check .
uv run black --check .
```

No test touches the network: 3DEP, NAIP, and R2 are replaced by fakes (`tests/dem_fakes.py`, `tests/imagery_fakes.py`, and `FakeS3` in `tests/test_upload.py`).
`tests/fixtures/manifest.sample.json` is regenerated by the tests and is what the site's
Zod schema is checked against, so commit it when it changes.

## Troubleshooting

- **`CRSError: The EPSG code is unknown` / `proj.db ... another PROJ installation`**: a
  system `PROJ_LIB` or `GDAL_DATA` (PostGIS sets both on Windows) is shadowing the libraries'
  own data. `flyover/__init__.py` clears them; run through `uv run` so it takes effect.
- **`3DEP rejected a ... request; fetching it in halves`**: normal. 3DEP answers 500 when one
  request spans too many source rasters, and the pipeline splits it.
- **Photo skipped, "taken outside the recorded track"**: the camera clock was off. Set
  `photo_time_offset_s` in the hike's TOML.
