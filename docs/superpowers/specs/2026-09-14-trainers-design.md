# Mental-Math Trainers: Zetamac + Optiver 80-in-8 — Design

**Date:** 2026-09-14
**Status:** Approved in brainstorming, pending spec review
**Scope:** Two private trainers under `/me`, with server-stored history, advanced statistics and progression tracking.

## 1. Goals and non-goals

**Goals**
- A Zetamac trainer that behaves exactly like arithmetic.zetamac.com, plus custom settings and targeted drills.
- An Optiver 80-in-8 trainer that is as faithful as public information allows, with an explicitly versioned difficulty profile.
- Every game and every question stored in Postgres, driving four families of stats: progress, weak spots, speed, and readiness.
- Keyboard-first on laptop/desktop.

**Non-goals (v1)**
- Mobile layout or an on-screen number pad.
- Multiple-choice answers, missing-operand questions, or percentage questions in the Optiver trainer.
- Leaderboards, sharing, or multiple users.
- Editing, deleting, or excluding past games.

## 2. Source facts

### Zetamac — confirmed from the site's own code
Read from `https://arithmetic.zetamac.com/` (form defaults) and `/dist/app.js?v=2` (game logic) on 2026-09-14.

| Parameter | Value |
|---|---|
| Operations | add, sub, mul, div — each a checkbox, all on by default |
| Addition | `a + b`, a ∈ [2,100], b ∈ [2,100] |
| Subtraction | draw the addition pair, show `(a+b) – a` (en dash), answer `b` |
| Multiplication | `a × b`, a ∈ [2,12], b ∈ [2,100] |
| Division | draw the multiplication pair, show `(a×b) ÷ a`, answer `b` |
| Sampling | each operand `min + floor(random() * (max-min+1))`; each problem's operation is uniform over the enabled ones |
| Answer check | on every `input` event, `value.trim() === String(answer)` means correct: advance at once, no Enter |
| Wrong answers | no state or feedback; the text stays until it matches |
| Timer | `setInterval` every 1 s; seconds left = `duration − floor((now − start)/1000)`; at ≤ 0 the input is disabled |
| Durations | 30 / 60 / 120 (default) / 300 / 600 s |
| Score | number of correct answers |
| Display text | "Seconds left: N", "Score: N" |

### Optiver 80-in-8 — decided with the user
Public sources conflict, and the user hasn't taken the test. These rules are **decisions**, not verified facts:

| Parameter | Value | Basis |
|---|---|---|
| Length | 80 questions, 8:00 hard stop | Confirmed by several sources |
| Flow | one question at a time, no going back | Confirmed by several sources |
| Skipping | not allowed | User decision |
| Answer format | typed number + Enter | User decision |
| Scoring | +1 correct, −1 wrong, 0 for unreached | User decision (majority of sources) |
| Timer/counter | hidden during the test, shown on results | One first-hand account; user decision |
| Calculator | none | Confirmed by several sources |
| Question types | integers, decimals, fractions | User decision |
| Pass line | ~55 net | Reported by prep sites; labeled an estimate in the UI |

## 3. Architecture

```
Browser (lazy-loaded /me/* chunk)                 Vercel functions                 Neon Postgres
┌──────────────────────────────┐   POST session   ┌─────────────────────────┐   ┌───────────┐
│ Game (pure generator+grader) │ ─► outbox ─────► │ api/trainers/sessions.js│ ─►│ sessions  │
│ Results screen               │                  │ api/trainers/stats.js   │ ◄─│ attempts  │
│ Stats tab (SVG charts)       │ ◄─ GET stats ─── │ api/trainers/drill.js   │   └───────────┘
└──────────────────────────────┘                  └─────────────────────────┘
                                  every handler: verifySession() + Zod validation
```

### 3.1 Routes (all behind `RequireAuth`, all `React.lazy`)
- `/me` — the hub. The Trainers section lists both trainers.
- `/me/zetamac` and `/me/optiver` — trainer page with **Play** and **Stats** tabs (`?tab=stats`).
- `/me/:trainer/game/:id` — detail for one game.

Lazy-loading keeps trainer code out of the public bundle, which is already ~900 KB.

### 3.2 Database (Neon Postgres via Vercel Marketplace, `@neondatabase/serverless`, env `DATABASE_URL`)

```sql
CREATE TABLE sessions (
  id              uuid PRIMARY KEY,            -- generated by the client; makes outbox retries idempotent
  trainer         text NOT NULL CHECK (trainer IN ('zetamac','optiver')),
  mode            text NOT NULL CHECK (mode IN ('standard','custom','drill')),
  config          jsonb NOT NULL,              -- full settings/rules used
  config_key      text NOT NULL,               -- stable hash of config; stats only compare equal keys
  profile_version int,                         -- Optiver difficulty profile version; NULL for Zetamac
  started_at      timestamptz NOT NULL,
  duration_ms     int NOT NULL,
  correct         int NOT NULL,
  wrong           int NOT NULL,                -- Zetamac: always 0
  unanswered      int NOT NULL,                -- Optiver: questions not reached; Zetamac: 0
  score           int NOT NULL,                -- Zetamac: correct; Optiver: correct − wrong
  created_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX sessions_series ON sessions (trainer, config_key, started_at);

CREATE TABLE attempts (
  session_id  uuid NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  idx         int  NOT NULL,                   -- 0-based position in the game
  qtype       text NOT NULL,                   -- e.g. 'z.mul', 'o.dec.div', 'o.frac.add'
  fact_key    text,                            -- normalized fact, e.g. 'mul:7x83'; NULL where not meaningful
  prompt      text NOT NULL,
  answer      text NOT NULL,                   -- canonical answer string
  response    text,                            -- submitted text; NULL if unreached/unfinished
  is_correct  boolean NOT NULL,
  time_ms     int,                             -- shown → accepted/submitted; NULL if unfinished
  corrections int NOT NULL DEFAULT 0,          -- Zetamac only (see 4.3)
  PRIMARY KEY (session_id, idx)
);
CREATE INDEX attempts_fact ON attempts (fact_key);
CREATE INDEX attempts_qtype ON attempts (qtype);
```

- Migrations are plain SQL files in `db/migrations/NNN_name.sql`. `scripts/migrate.js` applies them in order and records them in a `schema_migrations` table. Run with `npm run db:migrate`.
- `config_key` = SHA-256 of the canonical, key-sorted JSON of `{trainer, config, profile_version}`. It deliberately excludes `mode`, so a drill and a standard game can share a key. Stats therefore always filter on the pair (`mode`, `config_key`), and a drill never mixes into the standard series.

### 3.3 API (Vercel Node functions, ESM; limits from Zod schemas)
- `POST /api/trainers/sessions` — body `{ session, attempts[] }`, max 1000 attempts. Inserts the session and its attempts in one transaction, with `ON CONFLICT (id) DO NOTHING` so retries are safe. Returns `{ id, saved: true }`.
- `GET /api/trainers/sessions?id=` — one game's detail, including attempts.
- `GET /api/trainers/stats?trainer=&config_key=` — returns:
  - `series`: `[{id, started_at, score, correct, wrong, unanswered}]`
  - `byType`: `[{qtype, n, accuracy, median_ms, p90_ms, avg_corrections}]`
  - `pace`: average `time_ms` by `idx` bucket (Zetamac: buckets of 5 problems; Optiver: buckets of 10 questions)
  - `timeHistogram`: bins of `time_ms`
  - `slowest`: top 20 attempts by `time_ms`
  - `facts`: per-`fact_key` median time, accuracy, corrections and count
  - `wrongLog` (Optiver): the latest 50 wrong attempts
  - `configs`: every `config_key` for the trainer, with its game count and a label, for a settings picker
- `GET /api/trainers/drill` — weakest Zetamac facts from the last 20 standard games (see 4.4).
- Every handler: `verifySession()` (401 otherwise), `Cache-Control: no-store`, and the standard error shape `{ error, code, details? }`.
- The dev shim `vite.api-dev.js` gets extended to nested paths (`trainers/stats`); it still refuses `..`, `_` prefixes, and anything outside `api/`.

### 3.4 Client structure
```
src/private/trainers/
  core/rational.js       exact BigInt rationals: parse, add/sub/mul/div, equals, toCanonical
  core/rng.js            injectable RNG (Math.random in prod, seeded in tests)
  core/stats.js          rolling average, linear trend (score/week), percentiles, std dev
  core/configKey.js      canonical JSON + SHA-256 (Web Crypto)
  lib/api.js             fetch wrappers
  lib/outbox.js          localStorage queue; retries with exponential backoff (1s→60s), flushes on load and on 'online'
  zetamac/generator.js   port of Zetamac problem generators
  zetamac/drill.js       drill problem source (weak facts + normal mix)
  zetamac/ZetamacSetup.jsx, ZetamacGame.jsx, ZetamacResults.jsx
  optiver/profile-v1.js  difficulty profile (all mix weights and ranges)
  optiver/generator.js   template-based generator driven by a profile
  optiver/OptiverGame.jsx, OptiverResults.jsx
  stats/charts/          LineChart, Histogram, HeatGrid, BarList (hand-written SVG using .asc tokens)
  stats/ZetamacStats.jsx, OptiverStats.jsx, GameDetail.jsx
  TrainerPage.jsx        Play/Stats tabs
```

## 4. Zetamac trainer

### 4.1 Standard game
Behavior is exactly as in §2. The generators port Zetamac's `pg_add/pg_sub/pg_mul/pg_div` one to one, taking an injected RNG. Display strings copy the original: en dash for subtraction, `×`, `÷`.

### 4.2 Custom game
The setup screen shows the four checkboxes, all eight range fields, and the duration select. Validation:
- At least one operation is enabled.
- Every min ≤ max, and all values are integers in [0, 10000].
- A multiplication pair with a zero left operand is re-rolled for division, as in the original.

A game whose settings equal the defaults is saved with `mode: 'standard'`.

### 4.3 Extra logging (not shown during play)
- `time_ms` — from the problem appearing to the matching input. Timing uses `performance.now()`, not `Date.now()`, for millisecond precision; this does not change behavior.
- `corrections` — backspace/delete keypresses on the problem, plus each time the input reaches the answer's length without matching.
- `fact_key`:
  - add: `add:min(a,b)+max(a,b)`
  - sub: `sub:(a+b)-a`
  - mul: `mul:axb`, where a is the 2–12 operand
  - div: `div:(a*b)/a`
- The final unfinished problem at time-out is stored with `response` = the partial input, `is_correct = false`, and `time_ms = NULL`. It is excluded from speed stats and not counted as wrong.

### 4.4 Targeted drills
- **Source data:** attempts from the last 20 standard games that have `fact_key` and `time_ms`.
- **Weakness score per fact** (a fact needs ≥ 2 observations): `z(median_ms within its operation) + 1.5 × corrections_rate`.
- The top 40 facts by weakness become the drill pool.
- **Game:** each problem is a weak fact with probability 0.7 (sampled from the pool weighted by weakness) and a normal standard problem with probability 0.3. Timer, input and scoring are identical to a standard game. Duration is chosen from the standard options (default 120 s).
- **Availability:** drills unlock after 3 standard games; before that the button is disabled with an explanation.
- **Stats:** drill games have `mode: 'drill'`. Their attempts count toward per-fact mastery (`facts`) but not toward the standard score series.

## 5. Optiver 80-in-8 trainer

### 5.1 Flow
1. **Start screen:** the rules, then a "Start" button. Focus moves to the answer box.
2. **Test:** only the current question and the answer box are visible. No timer, no counter.
   - Input is limited to `[0-9.\-/]`.
   - Enter on empty or unparsable input (e.g. `3/`, `1/0`, `..`) does nothing, with a brief subtle shake.
   - Enter on a valid value submits it and moves to the next question immediately. There is no correct/wrong feedback during the test.
3. **End:** after 80 answers, or when the hard stop fires at 8:00 (`performance.now()`, checked every animation frame). A question in progress at time-out counts as unreached.
4. **Results:** net score, correct / wrong / unreached, questions reached, total time used, the pass-line comparison, and a per-question review.

### 5.2 Grading (exact)
- Parse the response as an integer, a decimal (`-?\d*\.?\d+`), or a fraction (`-?\d+/\d+`, denominator ≠ 0) into a BigInt rational.
- The canonical answer is also a rational.
- Correct ⇔ the two rationals are exactly equal. So `.5 = 0.50 = 1/2 = 2/4`, while `0.33 ≠ 1/3`.
- Canonical answer display: an integer if whole; otherwise a terminating decimal with ≤ 4 decimal places; otherwise a reduced fraction.

### 5.3 Difficulty profile v1 (`optiver/profile-v1.js`)
Each question draws a template by weight. All ranges are inclusive, and all results are exact.

| Family | Template | Weight | Generation |
|---|---|---|---|
| Integer | add | 12.5% | a, b ∈ [100, 999] |
| Integer | sub | 12.5% | a, b ∈ [100, 999], a ≥ b (result non-negative) |
| Integer | mul | 12.5% | 50%: a ∈ [12, 99] × b ∈ [3, 9]; 50%: a ∈ [11, 39] × b ∈ [11, 29] |
| Integer | div | 12.5% | divisor ∈ [3, 12] (70%) or [13, 25] (30%); quotient ∈ [11, 99]; show `divisor×quotient ÷ divisor` |
| Decimal | add/sub | 10% | two values with 1–2 dp in [0.1, 99.99]; for sub, larger first |
| Decimal | mul | 10% | 60%: x ∈ [0.05, 9.95] step 0.05 × n ∈ [2, 20]; 30%: x ∈ [0.1, 0.9] step 0.1 × y ∈ [1.1, 9.9] step 0.1; 10%: x ∈ [0.01, 0.09] × y ∈ [0.1, 0.9] |
| Decimal | div | 10% | divisor ∈ {0.2, 0.25, 0.3, 0.4, 0.5, 0.6, 0.8, 1.5, 2.5, 4, 5, 6, 8, 12}; quotient with ≤ 1 dp in [1, 99]; dividend = divisor × quotient, shown with ≤ 2 dp (re-roll otherwise) |
| Fraction | "p/q of N" | 7% | q ∈ {2, 3, 4, 5, 8, 10, 12, 20, 25}; p < q, gcd(p,q)=1; N ∈ [10, 200]; re-roll unless the result terminates in ≤ 2 dp |
| Fraction | add/sub | 7% | denominators ∈ [2, 12]; numerators < denominators; for sub, larger first; answer is the reduced fraction |
| Fraction | mul/div | 6% | numerators and denominators ∈ [1, 12], proper fractions; answer is the reduced fraction |

- **Order:** 80 independent draws. The same prompt never appears twice in one test; re-roll on a duplicate.
- **Terminating rule:** decimal-family answers always terminate (≤ 4 dp). Fraction-family answers may be repeating (e.g. 1/3); those must be entered as a fraction or an exactly equal value.
- **Calibration target:** a prepared test-taker averages ~6 s per question, so a strong run lands near the ~55 net pass line. This is an estimate. The UI states "Difficulty profile v1 — estimated from public reports."
- **Versioning:** a retune creates `profile-v2.js`. Sessions store `profile_version`, and stats never mix versions.
- `qtype` values: `o.int.add|sub|mul|div`, `o.dec.addsub|mul|div`, `o.frac.of|addsub|muldiv`.

## 6. Statistics and progression

Stats always filter by trainer, mode and `config_key` (and so by profile version). A picker lists the available configurations, defaulting to the standard one.

| Section | Zetamac | Optiver |
|---|---|---|
| **Progress** | score per game over time; 10-game rolling average; personal best; best per day; trend (least-squares slope, shown as "+x / week", only with ≥ 5 games over ≥ 3 days) | same, using net score |
| **Weak spots** | per operation: accuracy, median time, average corrections; times-table heat grid for 2–12 × 2–20 colored by median time (gray when no data); 20 slowest facts (≥ 2 observations); +/− split by carry/borrow count | per `qtype`: accuracy, median time; most-missed types; wrong-answer log (prompt, your answer, correct answer, date) |
| **Speed** | time histogram with median and p90; pace curve (median time by 5-problem bucket); slowest questions ever | histogram; pace curve by 10-question bucket; slowest questions |
| **Readiness** | recent scores beside community benchmarks, labeled "unofficial — sources disagree" (bands shown: 30 / 40 / 50 / 70) | last 10 net scores vs the 55 line; share of those ≥ 55; std dev of the last 10; average questions reached |
| **Game detail** | every problem: prompt, time, corrections | every question: prompt, your answer, correct answer, ✓/✗, time |

Server SQL does the aggregation. Client-side pure functions (`core/stats.js`) compute rolling averages, trends and std dev from the returned series.

## 7. States and error handling
- **Loading:** a quiet mono "Loading…" line in the page style. Charts reserve their space so the layout doesn't jump.
- **Empty:** "No games yet — play one to see stats," with a Play button. Individual charts show their own empty message when their data is too thin (e.g. trend needs ≥ 5 games).
- **Error:** an inline message with Retry. A 401 redirects to `/login`.
- **Saving:**
  - The results screen shows `Saved` or `Saving… (will retry)`.
  - Unsent games stay in the outbox across reloads. The trainer page shows "N games waiting to sync."
  - The outbox never drops an entry. Only a 4xx validation error flags it as failed, and failed entries are shown with details.
- **Mid-game navigation:** leaving asks for confirmation. An abandoned game is not saved.
- **Focus:** the game keeps focus in the answer box, and clicking elsewhere re-focuses it.
- **Accessibility:** results and stats have text equivalents (chart summaries as visually hidden text), and all controls are keyboard reachable.

## 8. Testing
- **Vitest** (new dev dependency). Tests live next to the source (`*.test.js`).
  - `rational`: parse/equality edge cases (`.5`, `-0`, `2/4`, `1/0`, huge numerators).
  - `zetamac/generator`: seeded runs respect the ranges; sub/div answers are always non-negative integers; operation frequency is uniform within tolerance over 10k draws.
  - `optiver/generator`: every template's answers are exact, decimal answers terminate, no duplicates within a test, mix weights hold within tolerance over 10k draws.
  - Grading: the equivalence table from §5.2.
  - `stats`: rolling average, trend, percentiles and std dev against hand-computed fixtures.
  - `outbox`: retry/backoff with a mocked fetch; no duplicates after a success.
  - API: Zod schemas reject malformed bodies; handlers return 401 without a session (DB mocked).
- **Manual browser check:** a full Zetamac game, a custom game, a drill, a full Optiver test including the time-out, the offline-save retry, and every stats page in empty and populated states.
- **Quality gate:** `npm run build` plus `npm test` pass.

## 9. Setup the user must do
1. Vercel dashboard → Storage / Marketplace → add **Neon** and connect it to this project. This sets `DATABASE_URL`.
2. Run `npm run db:migrate` locally, with `DATABASE_URL` in `.env.local`.
3. Redeploy.
