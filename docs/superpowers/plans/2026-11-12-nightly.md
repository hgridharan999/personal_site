# Nightly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/nightly` (private brief → answers → lock → grade → publish), `/notes` (public), the daily brief cron, and the hidden door on the homepage's Kilimanjaro band.

**Architecture:** Two new Vercel functions (`api/nightly.js` with `?action=`, `api/nightly-cron.js`) over shared modules in `api/_lib/nightly/`. Neon Postgres via migration 004. All state changes are single conditional SQL statements. Model calls go through one injected `model` object built on `@anthropic-ai/sdk`. Frontend: a lazy private page in `src/private/nightly/`, a public site-v2 page `src/site/NotesPage.jsx`, and a door inside `.kili-band`.

**Tech Stack:** Vite + React 18, react-router v7, Vercel Node 22 functions (ESM JS), `@neondatabase/serverless`, zod v4, vitest (node env), `@anthropic-ai/sdk`.

**Spec:** `docs/superpowers/specs/2026-11-12-nightly-design.md`. Read it before any task; section numbers below refer to it.

## Review Focus

1. **Double submit / double click:** the second request gets 409 and the first result stands (Task 5: `submit twice → second is 409`).
2. **Refresh during grading:** shows "Grading…", never Retry, and never runs a second grade (Task 5: `grade while grading → 202`; Task 6: `viewFor('grading')`).
3. **Session open after 3am Eastern:** submit is rejected with `NIGHT_CLOSED` and the draft survives in localStorage (Task 5: `submit of a closed night → 409 NIGHT_CLOSED`; Task 6: draft helpers).
4. **Model returns a URL it never searched:** the brief is rejected and never saved (Task 3: `verifyBriefUrls rejects unseen url`).
5. **Cron fired twice, or cron and Generate now overlap:** one brief, one model run, and the other caller gets 202 (Task 5: `generate when claim fails → 202, model not called`).

**Interfaces:**
- Consumes: `Brief`, `GradeResult`, `BlindTake`, `TYPES` and `USUAL_GROUND` from Task 2.
- Produces (`model.js`):
  - `MODEL = 'claude-sonnet-5-5'`.
  - `createDeadline(totalMs: number, now = Date.now): { signal: AbortSignal, remaining(): number, canRetry(): boolean }`. `canRetry` is `remaining() > 90_000`.
  - `buildBriefRequest({ night, types: string[], field: string }): object` returns Messages API params: the web search server tool (current version) with `max_uses: 8`, and a `submit_brief` client tool with `strict: true` and a JSON schema mirroring `Brief`, using `tool_choice` auto.
  - `buildGradeRequest({ stories, questions, answers: {idx, answer}[], take: {storyIndex, body} }): object`, using structured output for `GradeResult`.
  - `buildBlindTakeRequest({ story }): object`, using structured output for `BlindTake`. It receives only the story.
  - `collectSearchUrls(content: object[]): Set<string>`, taken from `web_search_tool_result` blocks whose `content` is an array.
  - `verifyBriefUrls(brief, urls: Set<string>): string[]` returns the unseen URLs (stories + niche). Compare after normalizing: lowercase host, strip trailing `/` and `#fragment`.
  - `createModel({ client = new Anthropic({ maxRetries: 1, timeout: 120_000 }) } = {}): { generateBrief({ night, types, field, deadline }): Promise<Brief>, grade({ stories, questions, answers, take, deadline }): Promise<GradeResult>, blindTake({ story, deadline }): Promise<string> }`.
  - On failure, the methods throw `ModelError(code, message)` with `code` one of `REFUSAL`, `NO_BRIEF`, `BAD_URLS`, `INVALID_OUTPUT`, `TIMEOUT`, `UPSTREAM`.
- `prompts.js`: the system prompts as exported string constants, carrying spec §5's rules verbatim in meaning:
  - largest consequences, not most coverage;
  - last 24 hours;
  - facts only, no analysis, predictions or opinion;
  - original wording;
  - a niche item from the given field, outside `USUAL_GROUND`, from roughly the last week to month;
  - grader scores reasoning quality, not agreement; one line naming the biggest gap; a follow-up only the writer could answer; never rewrite;
  - blind take is 3–5 sentences with a committed view.

`generateBrief` loop:
- Call `client.messages.create(req, { signal })`.
- On `pause_turn`, append the assistant content and re-call.
- On `refusal`, throw `REFUSAL`.
- If a `submit_brief` tool_use is present, parse it with `Brief`.
- If not, make one no-tools structured-output call over the text, then parse.
- Verify URLs. On `BAD_URLS` or `INVALID_OUTPUT`, retry the whole thing once, only if `deadline.canRetry()`.

`grade` and `blindTake` are each one structured-output call with the same refusal and validation handling.
